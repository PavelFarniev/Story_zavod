# ФОРМА — завод строительных материалов

Учебный проект сайта с каталогом из двенадцати товаров, заявкой на поставку, проверкой её статуса и кабинетами покупателя, менеджера и администратора. Название завода, ассортимент, цены, остатки и точка самовывоза демонстрационные.

## Запуск

Понадобится Node.js **22.13+** из ветки 22 или **24+** и npm. Из корня проекта:

```sh
npm ci
npm run build
npm start
```

Откройте [http://127.0.0.1:4173](http://127.0.0.1:4173). Первый запуск автоматически создаёт и заполняет `data/forma.sqlite`. База сохраняет заявки между перезапусками. `npm run dev` запускает тот же сайт с Vite и перезагрузкой при изменениях. Поддерживаются переменные окружения `PORT`, `HOST` и `DB_PATH`. При открытии через сетевой хост используйте HTTPS, браузеру нужен защищённый контекст для генерации кода заявки.

## Сценарий демонстрации

1. Выберите категорию, найдите товар по названию или артикулу и откройте его карточку.
2. Добавьте материалы в заявку, измените количество и выберите самовывоз или доставку.
3. Укажите тестовые контакты, отправьте форму и сохраните номер и код доступа.
4. Проверьте статус через кнопку «Статус заявки». Запрос возвращает состав, сумму и статус.

Демонстрационный адрес самовывоза — Подольск, Домодедовское шоссе, 7. В разделе «Доставка» можно раскрыть официальный виджет Яндекс Карт, открыть ту же точку отдельно или построить маршрут. Для виджета нужен интернет. Ключ разработчика для него не требуется.

Заявка фиксирует запрос на поставку. Остаток в каталоге справочный, стоимость доставки определяют при согласовании.

## Кабинеты и роли

| Вход | Возможности |
| --- | --- |
| [Покупатель](http://127.0.0.1:4173/account) | Самостоятельная регистрация, история своих заявок, состав и статус, добавление гостевой заявки по номеру и коду |
| [Менеджер](http://127.0.0.1:4173/manager) | Список заявок, контакты и состав, фильтр по статусу, согласование или отклонение |
| [Администратор](http://127.0.0.1:4173/admin) | Обработка заявок, создание и отключение аккаунтов, управление товарами, ценой, остатком, фото и видимостью |

### Первый вход администратора

В отдельном терминале, из папки проекта, создайте администратора с вашей почтой. Команда запишет его в ту же базу, которую использует сайт, и покажет случайный начальный пароль.

```sh
npm run admin -- admin@example.test "Администратор"
```

Войдите на странице [/admin](http://127.0.0.1:4173/admin) и смените пароль в «Настройках». Затем откройте «Аккаунты» → «Создать аккаунт» → «Менеджер». Менеджер входит на [/manager](http://127.0.0.1:4173/manager) с указанными при создании почтой и паролем. Общая кнопка «Кабинет» направляет сотрудника в его раздел после входа.

При нестандартном `DB_PATH` передайте тот же путь серверу и команде создания администратора. Для сайта за HTTPS-прокси установите `COOKIE_SECURE=1` и сохраните исходный заголовок `Host` в запросах к Node.js.

Гостевые заявки остаются доступны по номеру и коду. Покупатель может добавить такую заявку в историю, используя её исходный код. При обновлении существующей базы таблицы и поля для аккаунтов добавляются автоматически.

### Команды оператора в терминале

```sh
npm run orders -- list
npm run orders -- show 1
npm run orders -- status 1 review
npm run orders -- status 1 approved
```

Подставьте фактический номер заявки. Переходы: `new → review → approved`, из `new` и `review` также доступен `declined`.

## Проверка

```sh
npm run build
npm test
```

Одиннадцать тестов поднимают HTTP-сервер на временном локальном порту и используют отдельную временную базу. Они проверяют каталог, серверный расчёт суммы, повторные отправки, валидацию, сохранение, управление статусом и доступ к заявке. В Chromium отдельно проверены каталог на широком экране и оформление на ширине 390 px, включая потерю ответа после записи и успешный повтор. Дополнительно пройдены регистрация, оформление в аккаунте покупателя, обработка менеджером и управление товарами и аккаунтами администратором.

## API

| Метод | Маршрут | Результат |
| --- | --- | --- |
| GET | `/api/health` | Проверка доступности сервера |
| GET | `/api/catalog` | Категории и карточки товаров |
| POST | `/api/orders` | Создание заявки или возврат результата того же запроса |
| POST | `/api/orders/track` | Запрос статуса по номеру и коду доступа |
| GET | `/api/auth/me` | Текущий аккаунт |
| POST | `/api/auth/register`, `/api/auth/login`, `/api/auth/logout`, `/api/auth/password` | Регистрация, вход, выход и смена пароля |
| GET | `/api/account/orders`, `/api/account/orders/:id` | Заявки текущего покупателя |
| POST | `/api/account/orders/claim` | Добавление гостевой заявки в историю |
| GET / POST | `/api/staff/orders/:id` | Детали и изменение статуса, список через `GET /api/staff/orders` |
| GET / POST | `/api/admin/users`, `/api/admin/catalog` | Списки и создание записей, изменение через `POST` на путь с идентификатором |

Тело создания заявки содержит `code` (случайный UUID v4), `name`, `phone`, `method` (`pickup` или `delivery`), `address`, `comment`, `consent` и массив `items` из объектов с `productId` и `quantity`. Для статуса передаются `id` и `code`.
